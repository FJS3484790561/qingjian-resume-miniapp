## 本机运行

使用 Node.js **22.12.0 或更高的兼容版本**、npm 和现有锁文件。此 Node 版本的内置 `node:sqlite` 仍属实验 API，启动命令显式传 flag；生产运行环境将在部署阶段重新验证，当前不宣称生产就绪。

```powershell
npm ci
npx playwright install chromium
npm run server:dev
```

默认服务 <http://127.0.0.1:8787>，健康接口 `/health`。`server:dev` 明确开启本机开发登录；绑定非回环地址或 `NODE_ENV=production` 时拒绝启动开发登录。**开发账号标识只用于本机测试，不能作为正式身份认证。**

本机数据库自动创建于 `server/data/qingyu.sqlite`，包含账号、会话哈希与私有备份；启动按 `PRAGMA user_version` 执行事务迁移（当前 v4），不清空旧数据。服务器使用独立 `/var/lib/qingyu/qingyu.sqlite`。`server/data/`、SQLite/WAL/SHM、`.env` 均已忽略，不能提交或公开。换电脑需要单独迁移数据库；Git 仅同步代码。

另开终端启动 H5，或构建微信：

```powershell
npm run dev
# 微信开发者工具导入 dist/build/mp-weixin
npm run build:mp-weixin
```

小程序入口：**我的 → 账号与简历备份 → 连接本机开发测试账号**。本机 HTTP 仅用于模拟器；在开发者工具「详情 → 本地设置」取消合法域名校验。本机已在被忽略的构建目录 `project.private.config.json` 配置 `setting.urlCheck=false`，正式 `project.config.json` 保持校验开启；不要把此调试选项当作真机/上线方案。

生产构建默认 API 为 `https://resume.roomai.top`，开发模式默认为 `http://127.0.0.1:8787`；公开默认值在 `config/public-api.json`，`VITE_API_BASE_URL` 显式覆盖优先，修改后重新构建。本机 HTTP 开发才关闭本地校验；当前 HTTPS 验收始终开启。仅允许 HTTPS 或本机回环 HTTP，地址不包含凭据。真机的 127.0.0.1 指向手机自身，不能访问这台电脑。

## 微信正式登录配置

复制根目录 `.env.example` 为本机 `.env`，在其中填写服务端 `WECHAT_APP_SECRET`。AppID 已给定；不要把 AppSecret 发到聊天、写入 `src/`、`VITE_` 变量或公开仓库。密钥只在服务端读取。

```powershell
# 按实际部署配置 .env 后，使用不默认开启开发登录的命令
npm run server:start
```

`server:start` 默认关闭开发登录；检查 `.env` 中 `ALLOW_DEV_LOGIN=false`。客户端 `uni.login` 取得临时 code，服务端通过微信官方 HTTPS 接口交换 openid；session_key 不持久化、不回传，openid 只作为服务端身份索引。当前使用一次性随机 256 位 bearer 会话，数据库只存 SHA-256 哈希，7 天过期；退出撤销当前会话，删除应用账号会撤销全部会话。

未配置微信密钥时，接口返回 `503 WECHAT_NOT_CONFIGURED`；微信接口错误不会降级成开发登录。2026-10-29 已在微信模拟器使用真实 `wx.login` 与远程 code2session 验证 provider=wechat；密钥只在私有服务端文件。HTTPS 及微信合法域名已配置，真机网络、权限与上线隐私信息仍待验收。

## 接口

除健康和登录接口外，均需 `Authorization: Bearer <token>`；账号归属由会话决定，忽略客户端伪造的用户 ID。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/health` | 状态与允许的登录方式，不返回密钥 |
| POST | `/v1/auth/wechat` | `{code}` → 会话与应用用户 ID |
| POST | `/v1/auth/development` | `{deviceId}` → 仅显式启用且来自回环地址的测试会话 |
| GET | `/v1/me` | 当前应用用户 |
| POST | `/v1/auth/logout` | 撤销当前会话，JSON 体 `{}` |
| DELETE | `/v1/me` | `{confirmation:"DELETE_MY_ACCOUNT"}`，删除账号、全部会话和备份 |
| GET | `/v1/resumes` | 当前账号备份元信息列表，不含全文 |
| GET | `/v1/resumes/:id` | 全文与 revision |
| PUT | `/v1/resumes/:id` | `{resume,expectedRevision}`，首次 0，后续须匹配 |
| DELETE | `/v1/resumes/:id` | `{expectedRevision}`，删除前核对版本 |

错误统一 `{error:{code,message,fields?}}`。400 参数、401 会话、404 无权访问或不存在、409 版本冲突/数量限制、413 内容过大、429 过频、502 微信上游、503 未配置；500 不返回数据库路径、SQL 或凭据。

边界：JSON 请求最大 512 KiB，每个账号最多 100 份有效备份，每模块最多 100 条；这些是技术上限，不是竞品事实或收费规则。接口按 IP 每分钟 120 次，登录每分钟 10 次；代理信任默认关闭。服务器显式启用 `TRUST_LOCAL_PROXY=true`，仅信任回环 Nginx，并由它覆盖 X-Forwarded-For 为实际来源；外部伪造头不改变限流归属。

数据校验复用前端字段定义，服务端独立执行结构、长度、基础字段和模块顺序/唯一 ID 校验；富文本移除脚本、图片、链接与属性，仅保留当前支持的段落/列表/强调。所有 SQL 使用绑定参数。删除备份会清空其正文/标题，留下 ID 墓碑，避免延迟重试复活内容；删除账号会级联删除墓碑。SQLite 页面/WAL 与外部备份的物理擦除、加密、备份保留规则需在部署阶段定义，当前没有安全擦除承诺。

## 备份的产品约定

- 本机编辑与保存继续工作；不自动上传已有内容，不上传照片路径、模拟会员、模拟下载记录或设备设置。
- 主动备份取点击时已保存的内容快照，期间本机修改保留；页面中的本机/服务端身份和照片边界明确显示。
- 每次成功记录账号、服务端 ID、版本与本机草稿的关联；更新仅使用已知基准版本。409 保留本机正文与服务端新版本，可导入最新内容或另存副本，不自动覆盖。
- 导入总是创建新的本机草稿，原草稿保留，并绑定取到的版本；取数期间离页或切换当前草稿时取消导入，避免异步响应改变其他编辑页。删除服务端备份不删除本机草稿。
- 备份已成功而本机关联写入失败时明确提示，可从列表导入；不宣称操作从未到达服务端。超时和离页也可能出现已写入结果，重新进入应刷新列表核实，必要时删除重复副本。
- 退出请求失败时保留会话，方便重试；401 清理失效会话，过期请求的 401 不清掉后来建立的新会话。本机清空数据与删除服务端账号分开管理。
- AI 的独立演示、会员和独立模拟下载保留模拟文案；真实下载状态只由文件服务返回，不用模拟成功代替。

## 验收步骤

1. 启动 `server:dev` 并打开微信模拟器，进入备份页，看见「本机开发测试账号」，不把它当微信登录。
2. 新建独立虚构样例，备份后出现版本 1；本机照片保留，当前版本会在用户主动备份时包含已选照片；没有照片时保留纯文字备份。
3. 点导入，本机草稿数 +1，原草稿仍在；继续编辑后更新备份，版本 +1。
4. 退出后重新登录，备份仍在；重启服务，数据库内容仍在。不要清 storage 或删除数据库来模拟重启。
5. 删除服务端备份先取消，再确认；仅服务端内容被删除。本机草稿仍可编辑。账号删除会影响全部服务端备份，应只对测试账号操作。
6. 停止服务再刷新，出现可重试错误，本机简历不丢失；启动后恢复。

自动化：`npm test`、`npm run test:server`、`npm run type-check`、`npm run server:type-check`、H5/微信构建。官方 SDK 脚本 `scripts/wechat-backend-smoke.cjs` 使用 `QINGYU_AUTOMATOR_MODULE` 指向临时安装的 miniprogram-automator，且需事先用 CLI 开启自动化端口 9420；创建新虚构样例、真实请求本机服务并留下备份，不清空原有数据、不使用 API mock。

## 阶段 6：真实文件与私有照片

此阶段不增加商业收费或正式额度。服务仍为本机开发实例；用户在 Codex 网页测试，真实微信登录密钥选择稍后配置。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| POST | `/v1/photos` | `{dataUrl}`，校验规范化并按当前账号去重，返回私有 ID |
| GET | `/v1/photos` | 本账号照片元信息 |
| GET | `/v1/photos/:id` | 本账号照片 dataURL，鉴权/no-store |
| DELETE | `/v1/photos/:id` | 删除未被备份或进行中任务引用的照片 |
| POST | `/v1/exports` | `{requestId,resume,format:"pdf"或"docx"}`，返回真实任务；首次 202，重试同输入返回同记录 |
| GET | `/v1/exports` | 本账号真实文件与任务记录 |
| GET | `/v1/exports/:id` | 排队/运行/完成/失败/取消状态 |
| GET | `/v1/exports/:id/file` | 完成文件二进制，仍需 Authorization |
| POST | `/v1/exports/:id/cancel` | 取消未完成任务，JSON `{}`；完成后返回 409 并保留文件 |
| DELETE | `/v1/exports/:id` | 删除已终止任务及文件，进行中先取消 |

备份的 `basic.photoId` 必须属于当前账号，拒绝设备文件路径和其他账号的照片。前端主动读取本机照片上传，导入时取私有图片再新建本机草稿。账号删除级联清除所有照片/文件/记录；不注销微信账号。

照片原图不超过 4 MB，解码不超过 1600 万像素，仅 PNG/JPEG/WebP 静态照片；输出最长 1600×2000，剥离元数据。每账号最多 30 张/20 MB。导出每账号最多 50 条非删除记录、合计文件 50 MB、单个文件 10 MB；每账号最多 3 个未完成任务、全局 20 个、单 worker。任务超时 45 秒，重启中断标失败，晚到结果不能复活取消/删除的任务。上述为开发服务技术上限，不能当作正式会员或下载权益。

幂等键关联输入摘要，网络丢失后重试同一请求不增加重复文件；需要改变输入则用新键。成功或失败后清除任务正文快照；记录删除保留最小去重墓碑，账号删除清除墓碑。文件/照片保存在本机 SQLite BLOB；没有公开下载链接、自动外发或外部图片请求，当前未实现存储加密、定期清理和生产备份。

PDF 由独立 Chromium 排版，禁用脚本和外网请求；字体由服务端系统提供。安装依赖后运行 `npx playwright install chromium`。生产 Linux 还需要对应系统库与已授权中文字体，须在部署环境重新验收。DOCX 为原生可编辑段落、富文本强调/列表与照片，封面/三种布局以 Word 格式表达；Word/WPS 的分页可能与 PDF 和前端预览不同。

### 阶段 6 验收步骤

1. 保持 `npm run server:dev` 和 `npm run dev` 运行；在「我的 → 账号与简历备份」连接本机开发测试账号。
2. 新建虚构示例 → 制作/选择照片 → 应用到简历 → 手动备份；提示包含私有照片。导入新草稿后文字、排版和照片恢复，原稿保留。
3. 简历预览 → 下载文档 → 选 PDF/Word → 生成；实际任务完成后手动下载/打开。下载记录上半区为真实文件，下半区保留原有模拟记录。
4. 重新进入下载记录再下载，确认文件仍在；长文末尾完整。Word 模板详情生成的是虚构 DOCX 示例，不覆盖当前简历。
5. 生成中取消、离页、网络失败后重试：不得出现假完成或重复记录；离页不取消服务端任务，重新进入记录可查看。切换账号/草稿不沿用旧任务界面。
6. 照片/文件删除与账号注销先阅读确认；照片被引用时拒绝删除。取消删除保持数据。用隔离测试验证其他账号不可访问，不要为制造故障删除真实草稿。

`npm run test:render` 使用隔离内存账号、真实图片规范化和真实文档引擎，输出三套 PDF/DOCX 到忽略目录 `server/data/qa`。普通 `test:server` 的队列竞争测试用可控 renderer，不能替代这项实际引擎检查。2026-10-24 已完成真实引擎、PDF 渲染检查和 Codex H5 实际下载；微信新增下载/打开与真机仍待验收，DOCX 未进行 Word/WPS 实际软件视觉验收。


## 阶段 7：可配置 AI（2026-10-25）

用户选择先实现可配置接口、稍后选供应商。不是自动选择或调用任何第三方网页账户的授权。根 `.env.example` 和 `deploy/api.env.example` 提供 AI_API_ENDPOINT（完整 Chat Completions HTTPS 地址）、AI_API_KEY、AI_MODEL、AI_PROVIDER_LABEL，四项齐全才启用。默认超时 30 秒，AI_TIMEOUT_MS 可在 1000—60000 内配置；AI_DAILY_LIMIT 默认 20 次/账号/滚动 24 小时，含失败/取消，属于费用与资源保护，不能当作正式会员权益。

| 方法/路径 | 行为 |
| --- | --- |
| GET `/v1/ai/service` | 是否配置、用户可见服务商与模型；无密钥/endpoint |
| GET `/v1/ai/usage` | 当前账号 24 小时尝试/完成、供应商返回 token 汇总 |
| POST `/v1/ai/jobs` | requestId、section、source（1—10000 字纯文本）、consent=true、已同意的 service.provider/model |
| GET `/v1/ai/jobs/:id` | 本账号排队/运行/完成/失败/取消及结果；不返回输入原文 |
| POST `/v1/ai/jobs/:id/cancel` | 请求取消；晚到结果不能覆盖取消状态 |

服务端只用操作者配置的地址，客户端不能传 endpoint 或 key；HTTPS、拒绝跳转、响应 128KiB 上限、拒绝空结果/超过 10000 字/被截断结果，上游原始错误不出服务端。系统提示要求忠于事实，但模型仍可能出错，界面明确让用户核对并手改，不自动写入简历。

同账号同 requestId/相同正文与服务定义返回同任务；内容变化返回 409。失败任务需要新请求 ID，网络丢响应重试保留 ID。每账号同时最多一项，全局最多 10 项，单 worker；超时/取消立即释放本进程等待，向上游传 AbortSignal，无法承诺供应商一定停止计费。进程重启将中断任务标失败；账号注销级联删除并中止运行任务。

SQLite v4 新增 ai_jobs，暂存选中正文与模块名，终态清除原文；结果 24 小时后清除（每小时与访问时清理）。请求摘要/状态/时间/token 元数据保留用于幂等与统计，注销时删除；上线前需结合正式隐私规则确定长期保留期。当前没有按会员收费、扣次或正式订单。

AI 页默认真实服务，未配置时提交禁用，可独立切本机演示。实际发送前显示服务商和模型并要求勾选同意，只上传选中的纯文本与模块名，不上传整份简历/照片。手改、应用、撤销均检查草稿/条目与原文是否仍一致；账号变化清除结果。离页请求取消已知任务，晚到创建响应再补取消；网络完全中断可能无法确认供应商是否收到请求，不能伪称已撤回。使用新配置时刷新并重新勾选同意。

验收：未配置时检查禁用/本机演示；配置并重启后使用虚构正文测试真实结果、重复点击、取消、断网重试、手改/应用/撤销与后续编辑保护。当前实际只完成 H5 未配置与演示操作，以及隔离上游响应自动化；真实供应商、微信新页面和真机仍待验收。
